# Week 4

We have now exchanged our ideas for what the software should look/feel like. I came up with a main idea linked to the concept/experience of the software, starting with reading "The Art of Game Design" by Jesse Schell. The book explores game design from a user experience perspective rather than focusing on programming, which reflects our project direction. He separates game design in 4 main components: Mechanics, Story, Aesthetics, and Technology. He calls this the "elemental tetrad", so I used it to drive my ideation.

I explored different game engines and education software, and the one that stood out to me the most was Twine. I find the use of hypertext to be a simple method that is infinitely exploratory. This brought me to my software idea: a node-based engine that uses hypertext and language to link game mechanics, story and aesthetics. The nodes are templates that would allow users to link different ideas and concepts together to create a game that is immediately testable. 

I was tasked with working on the user flow.

It is not extremely detailed yet, and doesn't highlight the main features or games that will be on the app, but it shows the main user loop. A user would sign in, pick a game they would like to work on, and this would open a file that they can work on by creating and linking nodes of their choice. They can modify the nodes and test iteratively, going back and forth between simulating the game and working on it.
